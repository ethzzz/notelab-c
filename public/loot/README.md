# 摸金行动 · 物品 / 容器图片

放这里的图片会出现在 B 端「摸金行动 → 物品配置 / 容器配置」的**图片下拉**里。

- 支持 `png / jpg / jpeg / webp / gif / svg / avif`；
- 子目录最多 2 层（后端遍历深度上限 3），跳过点开头的隐藏文件；
- 清单由后端 `GET /api/loot-assets` **扫盘下发**（B 端浏览器读不到 C 端仓库），
  加图后刷新后台页面即可，不用改任何代码；
- 目录不存在时接口返回 `available:false`，B 端静默退回 emoji，不会报错。

存放的值就是浏览器可直接访问的 URL：`/loot/<相对路径>`（如 `/loot/it-016.png`）。

## 现有图标的命名约定

内置内容按 **`<物品 id>.png` / `<容器 id>.png`** 命名，与后台默认配置里的 `image` 字段一一对应：

| 文件 | 对应 | 数量 |
|---|---|---|
| `it-001.png` … `it-024.png` | 24 件内置物品 | 24 |
| `ct-crate.png`、`ct-tool.png`、`ct-ammo.png`、`ct-med.png`、`ct-safe.png`、`ct-cage.png` | 6 个内置容器 | 6 |

## 美术规格

- **风格**：扁平矢量插画 + 粗深色描边 + 高饱和明亮配色。
  小尺寸（前台格子约 20–34px）下细节多反而糊成一团，粗轮廓 + 大色块才立得住。
- **底色必须透明**：物品格自己带稀有度底色，图标带白底会在暗色页面上露出白方块。
- **画布**：192×192 PNG，内容按 alpha 裁剪后等比居中，四周留约 6% 边距
  （保证 30 个图标视觉重量一致，不会有的顶满有的偏小）。
- **体积**：单张控制在 40KB 以内（一局可能同时加载 20+ 张）。

## 生成与处理链路（可复用）

图标由图像生成模型按 **3×3 sprite sheet** 出图（一张 9 个，风格天然统一、成本是逐张生成的 1/9），
再用 `.agent/scripts/` 下的脚本切格 → 抠图 → 瘦身：

```bash
# 1. 切 3x3/2x2 网格，逐格抠成透明底并命名（名字按行优先，必须与图中实际顺序一致）
python .agent/scripts/sheet-slice.py <sheet.png> <out_dir> "it-001,it-002,..." --rows 3 --cols 3
# 2. 瘦身到 192px（裁边 → 等比 → 居中方画布 → PNG optimize）
python .agent/scripts/icon-shrink.py <out_dir> 192
# 3. 验收：合成到暗色底上看是否有白边残留、小尺寸是否可辨
python .agent/scripts/icon-preview.py <out_dir> <preview.png> --cols 6 --label
```

⚠️ 三个踩过的坑：
1. 图像生成的 `background: transparent` 参数**不生效**（产出是白底 RGB）→ 必须自己抠；
2. 抠图不能用全局阈值（白罐子/银色水壶会被挖空）→ 用「四角洪泛标背景 + 背景区软 alpha」；
3. 模型画出的格子顺序**可能和 prompt 顺序不一致**，命名前必须先看图核对。
